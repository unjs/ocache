# Query Parameters

By default, the **full query string** is part of the cache key. Therefore, `?color=red` and `?color=red&utm=x` use separate cache entries. Unrelated parameters, such as tracking tags and cache busters, can split the cache into many entries. This lowers the hit rate.

Set `allowQuery` to a list of allowed parameter names. **Only these parameters** vary the key. ocache ignores all other parameters:

```ts
const handler = defineCachedHandler(
  async (event) => {
    const url = event.url ?? new URL(event.req.url);
    const color = url.searchParams.get("color") ?? "default";
    return new Response(renderSwatch(color), {
      headers: { "content-type": "text/html" },
    });
  },
  {
    maxAge: 300,
    allowQuery: ["color"],
  },
);

// All of these share ONE cached entry (only `color` matters):
await handler({ req: new Request("https://shop.dev/swatch?color=red") });
await handler({ req: new Request("https://shop.dev/swatch?color=red&lang=en") });
await handler({ req: new Request("https://shop.dev/swatch?color=red&utm=ig") });
```

Matching is normalized and does not depend on order. For example, `?color=red&size=l` and `?size=l&color=red` use the same entry. Repeated array parameters, such as `?color=red&color=blue`, also match in any order.

> [!TIP]
> **Ignored parameters never reach the handler.** ocache removes parameters outside the allowlist from the URL that the handler receives. It does the same for cookies that are not allowed and [headers that are not declared](/handler#headers-the-handler-cant-see). Therefore, a handler cannot accidentally produce output from a parameter that is not in the cache key.

## Edge cases

- **Cache everything under one key.** An empty allowlist (`allowQuery: []`) removes the full query string. Every request to the path then shares one entry. The handler always receives a URL without a query.
- **Case-sensitive.** `allowQuery: ["color"]` does not match `?Color=red`.

> [!NOTE]
> **`getKey` overrides the full key.** If you provide a custom `getKey`, it decides the cache key instead of `allowQuery`. `allowQuery` no longer affects the key. However, ocache **still removes** parameters that are not allowed from the URL that the handler receives.
>
> ```ts
> defineCachedHandler(myHandler, {
>   maxAge: 300,
>   allowQuery: ["color"], // still strips other params from the handler's URL
>   getKey: (event) => new URL(event.req.url).pathname, // but this defines the key
> });
> ```
