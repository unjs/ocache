# Storage

Each cached function and handler owns its storage. By default, each instance gets a **new in-memory `Map`**. You can give an instance any backend that implements the small `StorageInterface`. You can also share one backend between many cached functions.

There is no global storage. Two cached functions that use the default storage cannot see each other's entries. This remains true when they use the same name and key. Therefore, independent libraries or apps in one process cannot collide by accident. To share a cache, pass the _same_ `storage` to all functions and handlers that must use it.

## The Storage Interface

A storage needs only two methods: `get` and `set`. Each method can be synchronous or return a promise:

```ts
interface StorageInterface {
  get<T = unknown>(key: string): T | null | Promise<T | null>;
  set<T = unknown>(key: string, value: T, opts?: { ttl?: number }): void | Promise<void>;
}
```

- `get(key)` returns the stored value, or `null` when the key is missing.
- `set(key, value, opts)` stores a value. `opts.ttl` is a lifetime in **seconds** (optional).
- Setting a **nullish** value (`null` or `undefined`) via `set` **deletes** the entry. This is how invalidation reaches your backend, so make sure your `set` handles it.

## Custom Storage

Pass your backend as the `storage` option. Here it is backed by Redis:

```ts
import { defineCachedFunction } from "ocache";
import type { StorageInterface } from "ocache";

const redisStorage: StorageInterface = {
  async get(key) {
    const raw = await redis.get(key);
    return raw === null ? null : JSON.parse(raw);
  },
  async set(key, value, opts) {
    // A nullish value means "delete this entry" (used by invalidation).
    if (value === null || value === undefined) {
      await redis.del(key);
      return;
    }
    // opts.ttl is in seconds — Redis' EX option expects seconds too.
    await redis.set(key, JSON.stringify(value), opts?.ttl ? { EX: opts.ttl } : undefined);
  },
};

const getUser = defineCachedFunction(fetchUser, { maxAge: 60, storage: redisStorage });
```

The interface is small, so you can use [unstorage](https://unstorage.unjs.io) drivers with a small adapter. Drivers are available for filesystems, Cloudflare KV, S3, Redis, and many other backends:

```ts
import { createStorage } from "unstorage";
import redisDriver from "unstorage/drivers/redis";

const unstorage = createStorage({ driver: redisDriver({/* ... */}) });

const storage: StorageInterface = {
  get: (key) => unstorage.getItem(key),
  set: (key, value, opts) =>
    value === null || value === undefined
      ? unstorage.removeItem(key)
      : unstorage.setItem(key, value, { ttl: opts?.ttl }),
};
```

## Sharing a Storage

Pass the same `storage` to every cached function or handler that should share a cache:

```ts
const storage = createMemoryStorage();

const getUser = defineCachedFunction(fetchUser, { maxAge: 60, storage });
const getPosts = defineCachedFunction(fetchPosts, { maxAge: 60, storage });
```

Functions still key entries by `base`, `group`, and `name`. Therefore, sharing a backend does not make them share entries. It gives them one connection, one eviction budget, and one place to purge.

> [!IMPORTANT]
> The `name` separates entries. It defaults to the function's or [handler's](/guide/handler#cache-key-name) name. If no name is available, ocache uses a hash of the source. Instances made by a factory or loop have identical source, so they get the **same** name. If they use shared storage, they also share entries. Give these instances an explicit `name`.

## Late Binding

Handlers are usually defined when the module loads. The real backend might not exist until the server starts. In this case, pass a **factory** instead of an instance. ocache calls it on the first cache read or write, not when you define the handler. It calls the factory at most once for each cached function or handler.

```ts
let storage: StorageInterface;

const handler = defineCachedHandler(renderPage, {
  maxAge: 60,
  storage: () => storage, // resolved on first use, once
});

// ...later, at server start
storage = redisStorage;
```

> [!NOTE]
> ocache stores the resolved storage on the options object that you passed. Give the standalone `invalidateCache()` and `expireCache()` helpers that original options object or the same backend. Both helpers throw when `options.storage` is unset. `resolveCacheKeys()` only computes keys and needs no storage. See [Invalidation & Expiration](/guide/invalidation).

## Memory Storage & LRU

The default storage is created with `createMemoryStorage`. Each cached function or handler gets a new one. It holds at most **10 000 entries** and **100 MB**. When either limit is exceeded, it evicts the least recently used entries (LRU). Reading or writing a key makes it the most recently used key.

Both limits apply, but they control different values. `maxSize` limits the entry **count**. `maxBytes` limits **memory**. `maxSize` alone does not limit memory. The retained bytes equal `maxSize × the size of each entry`. For cached HTTP responses, your pages determine the entry size. For example, 10 000 entries of 1 MB use 10 GB. Your process cannot catch an out-of-memory termination. Set a limit to `Infinity` or `0` to disable it:

```ts
import { createMemoryStorage } from "ocache";

// Change the ceilings.
const storage = createMemoryStorage({
  maxSize: 50_000,
  maxBytes: 512 * 1024 * 1024,
});

// Opt out of the entry ceiling, keep the byte budget.
const bigCache = createMemoryStorage({ maxSize: Number.POSITIVE_INFINITY });

const cached = defineCachedFunction(fn, { maxAge: 60, storage });
```

The byte value is an **estimate**. Strings, including cached response bodies, count as 2 bytes per character. This is the upper limit that an engine can retain. Binary values count the whole `ArrayBuffer` that they keep alive, even when the view covers a part of it. The estimate also includes the key bytes and a small cost for each entry. ocache intentionally estimates high because a budget that estimates low is not a reliable limit. Pass `sizeOf` to replace the estimate. Your function then calculates the full cost of each entry:

```ts
const storage = createMemoryStorage({
  maxBytes: 64 * 1024 * 1024,
  sizeOf: (value, key) => key.length + JSON.stringify(value).length,
});
```

> [!NOTE]
> An entry that exceeds `maxBytes` by itself is **not stored**. ocache also removes any previous value for its key. It does not evict the rest of the cache for an entry that still cannot fit. This prevents one large response from removing all other entries. Increase `maxBytes` if you cache a few very large values.

> [!NOTE]
> ocache also refuses a value that it **cannot measure**, such as an object with a property getter that throws. Storing it free of charge would remove the budget. Pass `sizeOf` to cache such a value with a charge that you control.

Memory storage also honors the per-entry TTL: expired entries return `null` and are cleaned up automatically.

## Multi-tier Caching

The `base` option adds a prefix to cache keys. Pass an **array** of prefixes to use multi-tier caching:

- **On read**, ocache tries each prefix in order and stops at the first hit.
- **After a miss**, ocache stores the entry under _every_ prefix.
- **After revalidation**, ocache writes the hit prefix and every earlier prefix.

```ts
import { defineCachedFunction } from "ocache";

const cachedFetch = defineCachedFunction(
  async (url: string) => {
    const res = await fetch(url);
    return res.json();
  },
  {
    maxAge: 60,
    base: ["/local", "/remote"], // read "/local" first, then "/remote"; write both
  },
);
```

Use this for layered setups, such as a fast local tier before a shared remote tier. Reads prefer the nearest tier. Misses populate every tier, while revalidation promotes a hit through the earlier tiers. A single string keeps everything in one tier. The default is `"/cache"`.

Invalidation and expiration operate across all tiers — see [Invalidation & Expiration](/guide/invalidation).
