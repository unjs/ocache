# Invalidation & Expiration

A cached function from [`defineCachedFunction`](/guide/functions) provides three methods to purge or refresh its entries: `.invalidate()`, `.expire()`, and `.resolveKeys()`. Each method takes the same arguments as the cached function. Use the standalone helpers when you do not have a reference to the cached function.

## Invalidate

`.invalidate()` **removes** cached entries from all base prefixes. The next call runs the function again and waits for a fresh value.

```ts
import { defineCachedFunction } from "ocache";

const getUser = defineCachedFunction(async (id: string) => db.users.find(id), {
  name: "getUser",
  maxAge: 60,
  getKey: (id) => id,
});

await getUser("user-123"); // resolves and caches

// e.g. after the user updates their profile
await getUser.invalidate("user-123");

await getUser("user-123"); // re-invokes the function, waits for the fresh value
```

> [!NOTE]
> `.invalidate()` and `.expire()` also cancel a resolution that is already in flight for the key. The call that started it still receives its value, but that pre-purge value is no longer written to storage, and the next call resolves again. The standalone helpers cannot do this, because they never see the cached function.

Use the standalone `invalidateCache()` when you do not have a reference to the cached function. For example, you can call it from a webhook or a different module. Pass the same key options: `name`, `getKey`, and any custom `group` or `base`. You must also pass **the same `storage`**:

```ts
import { invalidateCache } from "ocache";

// `cacheOptions` is the very object `defineCachedFunction` was called with.
await invalidateCache({ options: cacheOptions, args: ["user-123"] });

// Or reconstruct it — including the storage the entries were written to.
await invalidateCache({
  options: { name: "getUser", getKey: (id: string) => id, storage },
  args: ["user-123"],
});
```

> [!IMPORTANT]
> The standalone helpers rebuild the cache key from the options that you pass. They cannot see the original function. The `name`, `getKey`, `group`, and `base` must match the values that you used for caching. Otherwise, the helpers target a different key and do nothing. `resolveCacheKeys()` needs no storage. `invalidateCache()` and `expireCache()` throw when `options.storage` is unset. Pass the original options object or the same backend that contains the entries.

## Expire (SWR refresh)

`.invalidate()` removes an entry, so the next call must wait for a fresh value. In contrast, `.expire()` only marks the entry as **stale**. With SWR enabled, ocache continues to serve the stale value. The original `staleMaxAge` window still limits this behavior. The next access starts a background refresh:

```ts
const getUser = defineCachedFunction(async (id: string) => db.users.find(id), {
  name: "getUser",
  maxAge: 60,
  staleMaxAge: 300,
  swr: true, // required to actually serve stale values
  getKey: (id) => id,
});

// Next reader gets the stale value instantly; a refresh runs in the background
await getUser.expire("user-123");
```

> [!NOTE]
> Without `swr: true`, ocache resolves an expired entry in the foreground. Therefore, `.expire()` behaves much like `.invalidate()` for the next reader. The reader waits for a fresh value.

The standalone `expireCache()` works like `invalidateCache()`. Pass the same `maxAge`, `swr`, and `staleMaxAge` options that you used for caching. This preserves the remaining storage TTL instead of extending it:

```ts
import { expireCache } from "ocache";

await expireCache({
  options: {
    name: "getUser",
    getKey: (id: string) => id,
    maxAge: 60,
    swr: true,
    staleMaxAge: 300,
    storage,
  },
  args: ["user-123"],
});
```

> [!TIP]
> Use `.expire()` when you want to refresh without blocking readers. Use `.invalidate()` only when the next reader must get a guaranteed fresh value.

## Resolving keys

For advanced tasks, such as inspecting entries or running custom storage operations, use `.resolveKeys()`. It returns the raw storage keys for a set of arguments, with one key for each base prefix:

```ts
const keys = await getUser.resolveKeys("user-123");
// ["/cache:functions:getUser:user-123.json"]
```

The standalone `resolveCacheKeys()` does the same without a function reference. Again, pass matching key options. Read the entries from the storage that the function uses:

```ts
import { createMemoryStorage, defineCachedFunction, resolveCacheKeys } from "ocache";

const storage = createMemoryStorage();
const getUser = defineCachedFunction(fetchUser, {
  name: "getUser",
  getKey: (id: string) => id,
  storage,
});

const keys = await resolveCacheKeys({
  options: { name: "getUser", getKey: (id: string) => id },
  args: ["user-123"],
});

for (const key of keys) {
  const entry = await storage.get(key);
  // ...inspect or manipulate the raw entry
}
```

> [!IMPORTANT]
> `invalidateCache()` and `expireCache()` use `options.storage`. Storage belongs to **each cached function**, and there is no global fallback. Therefore, these helpers **throw** if `storage` is not set. They do not purge an empty store while the stale entry remains available. Pass the **same options object** that you used for caching, or at least the same `storage`. ocache stores the resolved storage on the options object. If you have the cached function, use its `.invalidate()` or `.expire()` method instead. A mismatched `name` or `getKey` still causes a silent no-op. Only a missing backend causes an error. The helpers also cannot cancel an in-flight resolution, so a call that is already running can write its pre-purge value after the helper returns.

See [Storage](/guide/storage) for the underlying store, and [HTTP Handlers](/guide/handler) for invalidating cached responses.
