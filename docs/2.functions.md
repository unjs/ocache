# Caching Functions

`defineCachedFunction` adds caching to any async function. It supports TTL, stale-while-revalidate (SWR), integrity checks, and automatic deduplication of concurrent in-flight calls.

```ts
import { defineCachedFunction } from "ocache";

const getRepo = defineCachedFunction(
  async (name: string) => {
    const res = await fetch(`https://api.github.com/repos/${name}`);
    return res.json();
  },
  {
    name: "github-repo",
    maxAge: 60, // cache each result for 60 seconds
  },
);

// First call fetches; calls within the next 60s return the cached value
const repo = await getRepo("unjs/ocache");
```

`cachedFunction` is an alias for `defineCachedFunction`.

## How it works

- **TTL** — ocache serves a cached value for `maxAge` seconds. It then resolves the value again.
- **Deduplication** — concurrent calls for the same key share one in-flight resolution. The underlying function runs only once during a burst of requests.
- **Integrity** — each entry is linked to a hash of the function and its options. If you change the function body or options, ocache automatically ignores old entries.

> [!IMPORTANT]
> `maxAge` defaults to **1 second**. If you want meaningful caching, set it explicitly.

> [!NOTE]
> SWR is **off by default**. Without SWR, ocache resolves an expired entry in the foreground. The caller waits for the fresh value. Set `swr: true` to serve the stale value immediately and refresh it in the background. See [Dynamic TTL](#dynamic-ttl) and [Invalidation & Expiration](/guide/invalidation).

## Options

```ts
const cached = defineCachedFunction(fn, {
  name: "my-fn", // cache key name (defaults to fn.name, then a source hash)
  maxAge: 60, // TTL in seconds (default: 1)
  swr: false, // serve stale while revalidating in background (default: false)
  staleMaxAge: 300, // max seconds a stale value may be served (SWR only)
  getMaxAge: (entry) => entry.value?.expires_in, // per-entry TTL from the value
  maxResolveTime: 30, // seconds a single resolution may take (default: 30)
  base: "/cache", // key prefix — string, or string[] for multi-tier caching
  group: "functions", // key group (default: "functions")
  storage, // where entries live — a StorageInterface or a factory returning one
  getKey: (...args) => args[0], // custom cache key from the arguments
  shouldBypassCache: (...args) => false, // when true, skip cache and call fn directly
  shouldInvalidateCache: (...args) => false, // when true, force a fresh resolve
  validate: (entry) => entry.value !== undefined, // reject an entry to re-resolve
  serialize: (entry) => entry.value, // prepare the value for storage
  transform: (entry) => entry.value, // reshape the value before returning
  onError: (error) => console.error(error), // handle cache read/write/SWR errors
});
```

By default, entries go into an in-memory store that is **private to this cached function**. To share entries, pass the same `storage` to more than one function. See [Storage](/guide/storage) to add a persistent backend. See [HTTP Handlers](/guide/handler) to cache full HTTP responses.

### staleMaxAge

`staleMaxAge` only applies when `swr: true`. It limits how long ocache can serve a stale value during a background refresh. After `maxAge + staleMaxAge`, the entry is fully expired. ocache also removes it from storage because this sum is its storage TTL. The next call resolves the value in the foreground.

**If you do not set it, the stale window has no time limit.** ocache serves the last successful value while the entry exists. It does not set a storage TTL. The entry remains until the storage backend evicts it. This is the [ISR](/guide/isr) pattern. `createMemoryStorage` evicts entries above [10 000 entries or 100 MB](/guide/storage#memory-storage--lru).

With `staleMaxAge: 0`, ocache **never** serves a stale value. After the entry expires, the request waits for revalidation even when SWR is on.

> [!NOTE]
> `maxAge: 0`, or a `getMaxAge` result of `<= 0`, caches nothing. The entry would expire as soon as ocache writes it. As a result, ocache resolves the value on every access and never stores it. If you omit an option, its default applies (`maxAge: 1`). An explicit `undefined` has the same effect. For example, `{ maxAge: undefined }` caches in the same way as `{}`. Therefore, a config made from optional values, such as `{ maxAge: rule.maxAge }`, cannot silently turn off caching.

## Cache keys

Each call uses a storage key built from `base`, `group`, and `name`. The key also includes a value derived from the arguments. This value comes from `getKey`, or from a hash of all arguments by default.

The `name` resolves as `opts.name || fn.name || anon_<hash(fn)>`:

- A named function (or one passed via a named binding) gets a stable, human-readable key.
- An anonymous inline function falls back to a hash of its source, so two different inline functions don't collide on one key.

ocache **escapes** the resolved `name` before it adds the name to the key. It does the same for every other segment. It removes characters outside `[A-Za-z0-9_]`. If this changes the value, it appends a hash of the raw value. An ordinary identifier stays unchanged. A `name` or `fn.name` that contains `:` or a space cannot be read as key structure. For example, `fn.bind(null)` uses the name `bound fn`.

> [!IMPORTANT]
> A source hash cannot distinguish two functions that have identical source but different closed-over variables. These functions share a key and repeatedly replace each other's entries. Give them an explicit `name` or `getKey`.
>
> The standalone [`resolveCacheKeys` / `invalidateCache` / `expireCache`](/guide/invalidation) helpers cannot see `fn`. When you use them to purge entries, always pass the same `name` that you used for caching.

```ts
// Custom key derived from a single id argument
const getUser = defineCachedFunction(async (id: string) => db.users.find(id), {
  name: "getUser",
  maxAge: 60,
  getKey: (id) => id,
});

await getUser("user-123"); // key includes "user-123"
```

## Dynamic TTL

Some values provide their own expiry. Examples include an OAuth token with `expires_in` and an upstream response with `max-age`. Use `getMaxAge` to get the lifetime from the resolved value instead of a fixed value.

`getMaxAge` runs after the resolver. It returns either a number of seconds, which is shorthand for `maxAge`, or `{ maxAge?, staleMaxAge? }`. The object form can also override the stale window. For that entry, returned values override the static options. They control both the freshness check and the storage TTL.

```ts
const getToken = defineCachedFunction(
  async () => {
    const res = await fetch("https://auth.example.com/token", { method: "POST" });
    return res.json(); // { access_token, expires_in }
  },
  {
    name: "oauth-token",
    // Cache each token for its own lifetime, minus a small safety margin
    getMaxAge: (entry) => Math.max(1, (entry.value?.expires_in ?? 60) - 5),
  },
);
```

> [!NOTE]
> Return `undefined`, or omit a field, to use the static option. A returned value of `<= 0` disables caching for that entry. ocache resolves it on every access. Negative values become `0`; they never mean "cache forever".

## Resolution deadline

Concurrent calls for one key share a single in-flight resolution. This deduplication makes the resolver run once during a burst. However, a resolver that **never settles** would block that key forever. Every later call would join the resolution that never finishes. One blocked upstream could make the key unavailable for the life of the process.

`maxResolveTime` sets a deadline in **seconds**. Like the other time values in this guide, it uses seconds. Its default is **30**. It covers the complete shared resolution. This includes the resolver and the `getMaxAge` and `serialize` hooks. A response body that never ends would be read during this period.

```ts
const getReport = defineCachedFunction(fetchFromUpstream, {
  name: "report",
  maxAge: 300,
  maxResolveTime: 5, // seconds — give up on a resolution after 5s
});
```

At the deadline, every caller that waits for the resolution rejects with a `TimeoutError`. The key then becomes free. The next call starts a new resolution.

```ts
try {
  await getReport();
} catch (error) {
  if ((error as Error).name === "TimeoutError") {
    // upstream is wedged — serve a fallback
  }
}
```

> [!NOTE]
> ocache does **not** cancel the abandoned resolver because it has no way to cancel it. The resolver continues and can still settle. However, no caller waits for its promise. ocache never serves its value or writes it to storage. It cannot overwrite a value that a later call cached.

A timed-out resolution is a **failed** resolution, like a resolver that throws. ocache evicts the entry that it was refreshing. Therefore, SWR does not continue to serve a value when its refresh is broken. With `swr: true`, the timeout also limits the background refresh. ocache reports this error through `onError` instead of throwing it because the related call has already returned.

You can use fractions. For example, `maxResolveTime: 0.5` is half a second. Pass `Infinity` or `0` to disable the deadline and wait without a time limit. Increase it for resolvers that are expected to be slow. A deadline can cause a resolution to fail when it would have completed just after the limit.

## Custom serialization

Some resolver outputs cannot be stored as they are. Examples include a `ReadableStream` and a class instance. Use `serialize` to convert the value to a form that you can store. Use `transform` to rebuild the usable value when you read it.

`serialize` runs once per resolution, immediately after the resolver. It still runs once when concurrent calls are deduplicated. Therefore, it is safe to consume a one-use source such as a stream.

```ts
const getReport = defineCachedFunction(
  () => generateReportStream(), // resolves a one-shot ReadableStream
  {
    name: "report",
    maxAge: 300,
    serialize: (entry) => streamToString(entry.value), // store as a string
    transform: (entry) => stringToStream(entry.value), // rebuild a stream on read
  },
);
```

## Cache status

`transform` receives an entry with a `status` field. This field shows how ocache served the value for this call. You can use it for metrics or observability. Its value is one of:

- `"miss"` — ocache resolved a fresh value because nothing was cached
- `"hit"` — ocache returned a fresh cached value
- `"stale"` — ocache served a stale value while a background SWR refresh runs
- `"revalidated"` — ocache resolved an expired value in the foreground before it returned

```ts
const getData = defineCachedFunction(fetchData, {
  name: "data",
  maxAge: 60,
  transform: (entry) => {
    metrics.increment(`cache.${entry.status}`); // "hit" / "miss" / ...
    return entry.value;
  },
});
```
